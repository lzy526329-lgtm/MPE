# 2D 鱼塘钓鱼玩法设计

## 目标

在 MPT 面板左侧增加“鱼塘”入口，提供与现有农场画风协调的手绘俯视钓鱼场景。玩家购买鱼饵，在限时窗口内收杆，钓获带随机重量的鱼。鱼获自动进入背包，可出售换取与农场、商店共用的金币。

首版成功标准：

- 完成“买鱼饵 → 抛竿 → 等待 → 咬钩 → 收杆 → 鱼获入包 → 出售”的闭环。
- 具备 5 种鱼、2 种鱼饵、图鉴进度和 100 条鱼获上限。
- 既有用户升级后，金币、农场和原背包内容不丢失。
- 钓鱼奖励只能由主进程结算，重复或伪造收杆不能重复获得鱼获。

## 非目标

首版不包含鱼竿升级、不同钓场、天气加成、任务、排行榜、联机、挂机钓鱼和水族馆养成。鱼影仅用于场景氛围，不直接代表本轮最终鱼种。

## 页面与视觉

### 入口

- 左侧玩法菜单新增“鱼塘”，位于“农场”附近。
- 鱼塘是独立 `fishing-page`，通过现有 `appNavigation` 显示和隐藏。
- 页面离开时取消本轮前端交互；再次进入时重新读取鱼塘状态。

### 场景

采用手绘俯视 2D 方案：

- 池塘占据主体区域，岸边包含草地、石块、水草和固定钓竿。
- 水面使用轻量 CSS 层叠动画表现流光、波纹与漂浮物。
- 鱼影在水下随机缓慢移动，仅作氛围装饰。
- 浮漂落点在安全水域内随机选取，抛竿、咬钩和收杆均有清晰动画。
- 尊重 `prefers-reduced-motion`：关闭持续鱼影和水面漂移动画，但保留必要状态提示。

### 信息布局

- 顶部 HUD：金币、当前鱼饵数量、图鉴进度。
- 底部鱼饵栏：普通鱼饵、高级鱼饵及各自库存。
- 选择鱼饵后点击水面抛竿，浮漂落在点击位置；收线支持空格键和备用按钮。
- 钓获弹层显示鱼名、稀有度、重量、最终售价，并在确认后关闭。
- 所有关键状态同时使用文字和动画表达，不能只依赖颜色。

## 核心交互状态机

前端状态为：

1. `idle`：选择鱼饵，点击水面确定浮漂落点并抛竿。
2. `casting`：鱼线展开，浮漂飞向所选落点并播放落水涟漪，禁止重复操作。
3. `waiting`：等待咬钩；提前点击收杆会失败。
4. `biting`：浮漂下沉并提示“鱼儿咬钩了”，开放 1.2 秒空格键收线窗口，同时保留点击按钮。
5. `resolving`：等待主进程校验和结算，禁止重复提交。
6. `caught`：展示鱼获弹层。
7. `failed`：展示“收杆太早”或“鱼儿脱钩”，随后回到 `idle`。

抛竿后 2.5～7 秒随机咬钩。页面隐藏不会暂停主进程判定时间。离开鱼塘、关闭窗口或应用退出都会使未结算轮次作废，已消耗鱼饵不返还。

## 鱼类和经济

### 鱼饵

| 鱼饵 | 价格 | 普通 | 少见 | 稀有 | 珍贵 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通鱼饵 | 2 | 75% | 20% | 5% | 0% |
| 高级鱼饵 | 6 | 45% | 30% | 20% | 5% |

同一稀有度内按鱼种权重选择。所有权重来自可测试的目录配置，业务逻辑不硬编码鱼名。

### 鱼种

| 鱼种 | 稀有度 | 重量范围 | 基础售价 |
| --- | --- | ---: | ---: |
| 鲫鱼 | 普通 | 0.2～1.0 kg | 3 |
| 鲤鱼 | 普通 | 0.5～2.5 kg | 5 |
| 草鱼 | 少见 | 1.0～5.0 kg | 8 |
| 鳜鱼 | 稀有 | 0.5～3.0 kg | 15 |
| 金色锦鲤 | 珍贵 | 0.3～2.0 kg | 30 |

最终售价以基础售价为中心，按重量在该鱼种范围内的位置获得 0.8～1.5 倍系数，四舍五入且最低为 1 金币。服务端在创建本轮时固定鱼种、重量和售价，前端只展示结果。

### 背包与出售

- 每条鱼获都是独立实例，包含唯一 ID、鱼种、重量、售价和钓获时间。
- 背包“鱼获”分类按鱼种分组展示数量，总价由实例售价求和。
- 支持出售单条鱼和出售全部鱼获。
- 鱼获最多保存 100 条。达到上限时禁止抛竿，不扣鱼饵。
- 图鉴以鱼种为单位永久记录；出售鱼获不会撤销已发现状态。

## 数据模型

在统一 `GameState` 中新增 `fishing`，并在 `inventory` 中新增 `baits` 与 `fish`：

```ts
type BaitId = 'basic' | 'premium'
type FishId = 'crucian' | 'carp' | 'grassCarp' | 'mandarin' | 'goldenKoi'

type FishCatch = {
  id: string
  fishId: FishId
  weightKg: number
  sellPrice: number
  caughtAt: number
}

type FishingState = {
  discoveredFish: FishId[]
  totalCaught: number
}

type GameState = {
  version: 2
  wallet: WalletState
  inventory: ExistingInventory & {
    baits: Record<BaitId, number>
    fish: FishCatch[]
  }
  farm: FarmCoreState
  fishing: FishingState
  migrations: GameMigrationState
}
```

`FishCatch` 数值在读取时逐字段校验。未知鱼种、非有限数值、负数售价和无效时间戳会被丢弃；超过上限时保留最早写入的 100 条合法鱼获。鱼获 ID 使用主进程生成的 UUID。

## 主进程模块和 IPC

新增 `electron/fishing/`：

- `fishCatalog`：鱼种、稀有度、重量和售价配置。
- `baitCatalog`：鱼饵价格与稀有度权重。
- `fishingEngine`：纯函数形式的抽取、重量、售价和状态校验。
- `fishingSession`：管理仅存在于内存中的当前抛竿轮次。
- `fishingIpc`：注册渲染层所需 IPC。

主要 IPC：

- `fishing:get-state`：返回金币、鱼饵、鱼获数量和图鉴。
- `fishing:cast(baitId)`：在统一存档事务内检查背包上限、扣除鱼饵，并创建单次令牌和咬钩时间。
- `fishing:reel(token)`：校验令牌、是否重复、当前时间是否在窗口内；成功时原子写入鱼获和图鉴。
- `fishing:cancel(token)`：使当前轮次失效，不返还鱼饵。
- `game:buy-bait(baitId)`：从共用金币扣款并增加鱼饵。
- `game:sell-fish(catchId)`：出售一条鱼。
- `game:sell-all-fish`：出售全部鱼获。

每个窗口最多存在一个活动轮次。令牌只在主进程内存中保存完整数据，渲染层拿到不透明 token、咬钩剩余时间和窗口长度。`reel` 无论成功或失败都立即消费令牌。

## 商店和背包接入

- 商店增加“鱼饵”页签，展示两种鱼饵、效果、价格和拥有数量。
- 背包增加“鱼获”页签，按鱼种分组，可展开查看单条重量和售价。
- 商店、背包和鱼塘继续订阅统一游戏状态变化，购买、钓获或出售后同步刷新金币与库存。
- 现有种子、食物、杂货、装饰和农产品行为不改变。

## 存档迁移

统一存档从版本 1 升级到版本 2：

- 版本 1 存档原样保留钱包、现有库存、农场和迁移标记。
- 新增空鱼饵库存、空鱼获列表、空图鉴和 `totalCaught = 0`。
- 缺失或部分损坏的钓鱼字段只重建钓鱼子树，不清空钱包或农场。
- 不重复发放初始金币，也不默认赠送鱼饵。
- 写回仍沿用现有原子临时文件加重命名机制和串行队列。

## 错误与边界

- 鱼饵不足、金币不足、背包已满、未知目录项和无效令牌返回明确错误码。
- IPC 异常时页面保留最近一次成功状态，允许重新加载；不能乐观增加鱼获或金币。
- 动画加载失败不影响状态判定，页面退化为文字和按钮反馈。
- 重复点击、并发 IPC、过早收杆、超时收杆和重复令牌都不能产生鱼获。
- 系统时间变化导致窗口失效时按失败处理，不补发奖励。

## 测试

### 单元测试

- 两种鱼饵的稀有度权重、鱼种选择和边界随机数。
- 各鱼种重量范围与售价上下界。
- 鱼获校验、100 条上限、图鉴去重。
- 购买鱼饵、单条出售、全部出售和金币原子变化。
- 抛竿扣饵、成功收杆、过早、超时、重复和伪造令牌。
- 版本 1 到版本 2 迁移及局部损坏修复。

### 渲染层测试

- 页面状态机只允许合法迁移。
- 不同状态下按钮文案、禁用状态和提示正确。
- 商店鱼饵页签与背包鱼获页签正确汇总。
- 导航离开触发取消，重新进入刷新状态。

### 手工验收

- 完整体验普通和高级鱼饵各若干轮。
- 验证低动画偏好、窗口缩放、快速切页和应用重启。
- 验证购买、钓获和出售后鱼塘、商店、背包金币保持一致。
