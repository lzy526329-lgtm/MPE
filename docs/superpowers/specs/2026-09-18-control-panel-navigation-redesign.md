# 控制面板导航与 UI 重构设计

## 背景

当前主窗口把宠物设置二级菜单、玩法入口和工具入口混在同一个侧栏中。`appNavigation.ts` 在切换页面时通过 `hidden` 隐藏 `#pet-settings-nav` 和部分侧栏按钮，导致用户从宠物设置进入其他页面后入口消失；返回路径也分散在多个按钮监听器中，页面状态和菜单状态容易不同步。各页面继续复用旧的全局样式，视觉层级、间距和操作区缺少统一规则。

## 目标

1. 保留现有全部页面、Electron API 和页面业务操作。
2. 任何页面切换后，全局一级菜单始终可见；当前页面有唯一明确的 active 状态。
3. 将宠物设置的六个分类收纳为设置页内部的二级导航，避免污染全局导航。
4. 用一套共享的页面壳、颜色变量、卡片、按钮、表单和反馈样式重做主窗口 UI。
5. 桌面宽度和窄窗口下都能访问全部入口，不依赖隐藏元素恢复菜单。
6. 用测试锁定菜单可见性、active 同步、返回行为和无效页面保护。

## 非目标

- 不删除图片、视频、文件、PDF、电脑信息、磁盘清理等现有工具。
- 不改变宠物状态、提醒、农场、鱼塘、商店、背包、账号等业务接口。
- 不改变 Electron 窗口、托盘、桌宠透明窗或资源路径逻辑。
- 不在本次重构中引入新的 UI 框架或第三方组件库。

## 信息架构

全局侧栏固定展示四组入口：

### 桌宠

- 宠物设置（默认首页）
- 与我对话
- 个人小屋

### 玩法

- 农场
- 鱼塘
- 商店
- 背包

### 工具箱

- 图片压缩
- 图片抠图
- 视频去水印
- 文件压缩
- 文件解压
- PDF 工具箱
- 拉取图片
- 电脑信息
- 磁盘瘦身
- 序列帧预览
- 视频转序列帧

账号与同步作为侧栏底部的独立入口。隐私提示固定在底部。全局菜单按钮都绑定 `data-page`，由统一导航处理器委托，不再为每个按钮分别写切换监听器。

宠物设置页内部保留六个二级分类：基础信息、形象、外观与行为、状态、交流提醒、关于与更新。二级分类仅控制 `pet-settings-root` 内的面板，不参与全局页面的 `hidden` 逻辑。

## 导航状态模型

`appPages.ts` 增加不可变的页面注册表，每条记录包含：

```ts
type AppPageDefinition = {
  id: AppPageId
  title: string
  eyebrow: string
  group: 'pet' | 'play' | 'tool' | 'account'
  navLabel: string
  showInGlobalNav: boolean
}
```

注册表是唯一的页面标题和分组来源。`APP_PAGE_TITLES` 继续导出以兼容已有调用，但由注册表派生。

`appNavigation.ts` 提供以下行为：

- `navigateToPage(pageId)`：验证注册表中的页面 ID；切换所有 `.tool-page` 的 `hidden`；更新页面标题、眉题和侧栏按钮的 `aria-current` / `active`；更新返回按钮是否显示。
- `getCurrentPage()`：返回当前页面。
- `onPageChange(listener)`：保留现有监听接口。
- `setupAppNavigation()`：绑定返回按钮和全局 `[data-page]` 委托；监听 Electron 主进程导航；初始化首页。

全局侧栏不再由 `syncToolbar` 隐藏。返回按钮只在非首页显示，点击后回到宠物设置。切换页面时保留设置页当前二级分类，不自动重建设置页 DOM。

## 页面壳与视觉系统

`main.ts` 将主窗口外壳调整为：

- `app-shell`：完整视口布局。
- `sidebar`：品牌、分组导航、底部账号和隐私提示。
- `workspace`：统一页面头部、面包屑/返回操作和内容区。
- 页面头部包含 `eyebrow`、标题、说明和可选操作区。

`style.css` 建立以 CSS 变量为核心的主题：

- 页面底色使用淡紫灰，内容卡片使用高透明度白色。
- 主色为暖紫，成功/提醒/危险分别使用绿色、琥珀色、珊瑚色。
- 统一 12/16/20px 圆角层级、8/12/16/24px 间距层级和柔和阴影。
- `.nav-group`、`.nav-group-title`、`.nav-item` 负责分组与 active 状态。
- `.workspace-toolbar`、`.workspace-header`、`.workspace-content` 负责所有页面的头部和内容宽度。
- `.panel`、`.preview-card`、`.settings-card`、`.result` 复用同一边框、背景和阴影规则。
- 对 `prefers-reduced-motion` 禁用非必要位移和过渡。

窄窗口（小于 900px）下侧栏变为顶部横向滚动的导航带；分组标题保持可读，所有入口继续存在。页面内容宽度改为流式布局，工具编辑器从双列降为单列。小于 640px 时操作按钮允许换行，页面标题字号下降。

## 设置页重构

`petSettingsPage.ts` 保留现有渲染与事件逻辑，只调整根 DOM：

- `pet-settings-layout` 包含设置页头部和二级导航。
- 二级导航按钮使用 `data-pet-tab`，继续调用 `switchPetSettingsTab`。
- 现有六个 `data-pet-panel` 面板保持 ID 和字段 ID 不变，确保 API 事件和测试不受影响。
- 顶部概览卡保留当前宠物名称、状态、等级和金币，但移动到设置页头部。

## 错误与边界行为

- 无效 `pageId` 被忽略，当前页面和菜单状态保持不变。
- 页面 DOM 缺少某个可选导航元素时，导航仍切换页面；同步函数只更新存在的节点。
- Electron 推送未知页面 ID 时不抛异常，回退到宠物设置。
- 当前页面按钮重复点击不重建页面，只同步状态并通知监听器一次。
- 设置页二级导航只接受六个已知 tab，未知 tab 回退到 `profile`。

## 测试策略

新增或扩展 `src/__tests__/appNavigation.test.ts`：

1. 初始化后全局分组和页面按钮保持可见。
2. 连续切换设置、工具、玩法、账号页面后，所有全局入口仍可见。
3. 当前页面只有对应按钮获得 active / `aria-current="page"`。
4. 返回按钮只在非首页可见，并能回到宠物设置。
5. 无效页面 ID 不改变当前页面。
6. Electron 主进程推送未知页面时回退到首页。

扩展 `src/__tests__/appPages.test.ts`，验证注册表覆盖所有页面且分组正确。现有所有页面测试、完整 Vitest 测试和带 `GAME_API_BASE_URL` 的生产构建必须继续通过。

## 实施顺序

1. 先新增页面注册表和导航回归测试，验证当前实现能复现菜单消失问题。
2. 实现集中式导航状态同步和全局事件委托。
3. 调整 `main.ts` 外壳与菜单分组，接入 `data-page`。
4. 调整设置页根结构，保持内部字段和业务事件兼容。
5. 重做共享 UI 样式和响应式规则。
6. 运行完整测试、类型检查、生产构建并做手动页面切换检查。
