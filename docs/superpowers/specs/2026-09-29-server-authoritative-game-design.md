# 桌宠本地与账号游戏服务端权威设计

## 1. 背景与目标

当前桌宠、农场、商店、背包和钓鱼共用本地 `game.json`，账号系统通过整份存档上传和下载进行可选同步。农场偷取已经由服务端同时修改两个玩家的云存档，但客户端普通同步流程以“上传本地存档”为主，导致服务端主动写入的奖励可能停留在云端，背包显示旧数据。

本期将数据边界调整为：桌宠普通功能继续本地运行，账号游戏数据由服务端作为唯一真实来源。客户端只保留按账号隔离的缓存，用于快速渲染和断网提示；登录后的经济和玩法操作必须由服务端校验并提交。

目标包括：

- 农场、商店、背包、钓鱼、好友农场和好友对战要求登录后使用。
- 金币、种子、农产品、食物、用品、装饰、鱼饵、鱼获、农场状态和玩法结算由服务端控制。
- 首次登录自动迁移现有本地游戏进度；云端已有存档时沿用冲突选择流程。
- 退出或切换账号时不泄露上一个账号的游戏缓存。
- 桌宠展示、移动、聊天、普通互动、配置、动画和工具箱继续支持未登录使用。

## 2. 数据边界

### 2.1 本地数据

`pet.json` 及现有桌宠相关文件继续保存：

- 桌宠配置、位置、大小、角色和动画绑定。
- 桌宠普通状态、对话记录、记忆、提醒和本地成长数据。
- 工具箱设置以及与账号无关的本地偏好。

桌宠可以在未登录状态启动和互动。桌宠喂食、清洁等消耗账号背包食物或用品的操作属于账号游戏功能；未登录时显示登录提示，不创建一套绕过背包的本地库存。

### 2.2 服务端数据

服务端保存并校验现有 `GameState` 中的：

- 钱包金币。
- 食物、用品、种子、农产品、装饰、家具、鱼饵和鱼获。
- 农场地块、作物生长、天气、虫害、等级经验和收获结果。
- 钓鱼消耗、随机结果、鱼获容量和出售结果。
- 好友关系、好友农场访问、偷取次数、访问日志和对战结算。

服务端继续使用版本化游戏存档作为持久化载体，但日常写入通过服务端命令完成。客户端不能通过普通请求提交任意完整库存来修改金币或物品。

### 2.3 本地缓存

缓存按账号隔离，例如 `userData/game-cache/<userId>/game.json`。缓存只用于：

- 已登录用户打开页面时快速展示最近一次服务端状态。
- 服务端请求期间展示旧状态和加载状态。
- 请求失败时保留可读画面并提示重试。

缓存更新必须发生在服务端命令成功之后。切换账号时停止旧账号同步、清除内存中的旧视图，并加载新账号缓存或重新拉取服务端状态。

## 3. 登录门槛与页面行为

应用启动不要求登录，默认进入桌宠页面。以下入口在导航点击时检查账号状态：

- 农场。
- 商店。
- 背包。
- 鱼塘。
- 好友农场和好友对战。

未登录时不打开对应页面，直接导航到账号页并显示“登录后使用”说明。登录成功后返回用户刚才尝试进入的页面。图片处理、压缩、PDF、系统信息等工具不受账号门槛影响。

页面打开后仍需处理会话过期：服务端返回会话失效或封禁时，清空账号游戏视图，跳转账号页，并保留桌宠窗口和本地状态。

## 4. 首次登录与迁移

### 4.1 云端为空

1. 读取当前本地 `game.json` 并校验版本、校验和和游戏结构。
2. 登录后请求服务端当前存档。
3. 云端为空时，通过一次受控的迁移接口上传本地存档。
4. 服务端校验完整 payload，创建账号的初始版本并返回规范化状态。
5. 客户端将返回状态写入账号缓存，记录云端 revision，后续不再使用普通整档上传。

### 4.2 云端已有存档

如果本地缓存和云端校验和不同，显示当前已有的本地/云端摘要，沿用现有“使用本地”或“使用云端”选择。选择完成后只允许服务端按 revision 条件提交，避免覆盖登录期间其他设备的新版本。

### 4.3 多账号隔离

首次迁移成功后，本地缓存以用户 ID 分目录保存。退出登录不会删除桌宠文件，但必须停止旧账号的游戏同步、清空旧账号状态并隐藏账号游戏页面。再次登录时只读取对应用户目录。

## 5. 服务端命令接口

新增统一的账号游戏状态接口：

- `GET /api/game/state`：返回当前账号的完整游戏视图和 revision。
- `POST /api/game/migrate`：仅用于首次登录或明确的冲突恢复，接受一次完整存档并要求 `baseRevision`。
- `POST /api/game/command`：执行一个已定义的游戏命令并返回提交后的状态、revision 和结果摘要。

命令请求包含 `requestId`，服务端按账号和请求 ID 做幂等处理。命令体只包含动作和参数，不包含客户端自报的金币、库存或随机结果。第一批命令覆盖：

- 农场：播种、浇水、除虫、收获、解锁地块。
- 商店和背包：购买种子、食物、用品、装饰、家具和鱼饵；出售农产品和鱼获；使用食物和用品。
- 钓鱼：开始钓鱼、完成收线、提交服务端生成的鱼获结果。
- 好友玩法继续使用现有好友农场和对战接口，并返回更新后的账号状态或 revision。

服务端命令在事务中锁定账号存档，重新读取并结算当前状态，校验前置条件，写入新 revision，再返回规范化状态。随机收益、每日限制、库存扣减和容量限制都在服务端产生或验证。

现有 `GET/PUT /api/game/save` 保留为迁移和兼容接口，日常客户端操作不再调用 `PUT` 上传完整 `GameState`。

## 6. 客户端结构调整

新增账号游戏服务层，负责：

- 读取账号状态和缓存。
- 发起带 `requestId` 的服务端命令。
- 在命令成功后原子写入账号缓存并发布 `game:state-changed`。
- 处理加载、会话失效、网络错误和重复请求。

现有 `electron/game/gameIpc.ts`、农场 IPC 和钓鱼 IPC 保留渲染层接口，内部改为调用账号游戏服务层。这样农场页、商店页、背包页和钓鱼页不需要各自实现登录、缓存或冲突逻辑。

本地纯桌宠调用继续使用现有 `pet.ts` 和 `pet.json` 流程。桌宠中消费食物/用品的入口改为调用账号游戏服务层，成功后再更新本地宠物的饱食度或卫生状态。

## 7. 错误和离线行为

- 未登录：页面入口拦截并跳转账号页。
- 会话过期或账号封禁：清除账号游戏状态，停止命令重试，并提示重新登录。
- 网络失败：保留最近缓存，页面显示“暂时无法同步”；不把本地操作标记为已成功，也不允许离线修改库存。
- 请求超时或重复点击：使用 `requestId` 幂等，客户端在确认结果前禁用同一操作按钮。
- 服务端业务失败：返回明确的库存不足、金币不足、作物未成熟、鱼获背包已满等错误，客户端只刷新服务端返回的状态。
- 缓存损坏：丢弃当前账号缓存并重新拉取服务端状态；服务端存档不受本地文件损坏影响。

## 8. 分阶段实施

### 阶段一：账号门槛和缓存隔离

- 为游戏页面增加登录门槛和登录后返回路径。
- 将现有本地游戏缓存迁移到按账号目录。
- 完成首次登录自动迁移、云端冲突选择和退出清理。
- 继续使用现有同步流程作为过渡，但禁止未登录进入账号游戏页面。

### 阶段二：服务端状态和命令

- 增加 `GET /game/state`、`POST /game/migrate` 和命令服务。
- 先迁移商店、背包和农场的购买/收获操作。
- 再迁移钓鱼结算、出售和桌宠消耗背包物品的操作。
- 将好友农场偷取返回的服务端状态直接写入账号缓存。

### 阶段三：停用日常整档上传

- 日常客户端不再调用完整存档 `PUT`。
- 保留迁移和明确冲突恢复入口。
- 删除不再使用的离线写入和自动覆盖逻辑，更新账号页文案。

## 9. 验证范围

- 页面导航：未登录点击每个账号游戏入口都会跳转登录；工具和桌宠页面仍可打开。
- 迁移：空云端自动上传本地进度；已有云端显示冲突并按选择保留正确版本；两账号缓存互不读取。
- 命令事务：金币、库存、作物状态、鱼获和每日限制在并发请求下保持一致。
- 客户端同步：服务端偷取或其他服务端写入后，背包和农场收到最新状态；重复 `requestId` 不重复扣款或发奖。
- 退出与会话失效：旧账号数据不再显示，桌宠普通功能继续工作。
- 构建和现有客户端、服务端单元测试全部通过。
