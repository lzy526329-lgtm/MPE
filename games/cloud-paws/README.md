# 云端小爪 · 一起登顶

在桌宠主窗口「玩法 → 云端小爪」或桌宠右键菜单进入。支持单人离线练习，以及登录后的 2–5 人同场闯关。所有模式均已移除星星收集。

## 组队与规则

登录桌宠账号，点击「组队闯关 → 创建房间」，把六位房间码告诉伙伴。其他玩家输入房间码加入，所有人准备后由房主开始，倒计时 3 秒一起出发。每房间最多 5 人，开局后不能中途加入新玩家。

玩家之间、玩家与木杆之间都有真实物理碰撞。碰撞本身不会回档，掉出关卡才返回个人最近的存档点；也可按 R 主动返回。每人分别保存第 12、24、36、48 段的进度。按到达终点的先后排序；先到的玩家等待伙伴，全部完成后房主可再开一局。离开房间会转移房主；断线保留位置 20 秒，期间角色不参与碰撞，恢复连接可继续，超时退出房间。

联机时 Esc、失去焦点或切换桌宠功能只停止自己的输入，比赛继续。单人练习时则暂停整个场景。

## 操作

- 鼠标转视角，左键或空格跳跃；右键拖动也可转镜头，滚轮缩放。
- WASD / 方向键随镜头移动，Shift 加速，C 看向下一段，Q / E 转向。
- R 返回自己的存档点；Esc 释放鼠标并打开菜单。
- 触屏拖动画面转视角，屏幕按钮控制方向和跳跃。
- 音效默认关闭，可点右上角音符开启。

## 联机服务与发布

复用现有账号服务的 `/ws/game` WebSocket，命令类型以 `cloud_paws.` 开头。会话凭证仅留在 Electron 主进程，嵌入页面通过校验来源的消息桥发送有限的操作指令。服务端在每房间的 Rapier 场景中统一计算 60 Hz 物理和终点排名，20 Hz 广播快照；客户端平滑显示快照，不提交位置或成绩。

客户端源代码和服务端逻辑在此目录维护。`npm run build:cloud-paws-server` 将 `server/rooms.js` 及完全相同的物理、关卡、Rapier WASM 打包到相邻 `gognju-server/server/game/cloudPawsRuntime.cjs`。该生成文件随服务端代码一起提交和部署，服务端无需安装新运行依赖。修改房间/物理/关卡后必须重新生成，也可向脚本传入其他输出路径。应用构建不自动改动另一个仓库。

必须同时更新服务端 `game/realtime.js` 和生成的运行文件，重启账号服务，并更新客户端，才能在正式服务器组队。只更新桌宠时会显示联机服务未响应，不会创建假房间。当前房间仅保存在内存：服务端重启会结束房间；同一账号服务须以单实例或固定 WebSocket 路由运行，不支持跨进程共享房间。最多 64 个同时存在的房间，等待房间 10 分钟、开局后总计 60 分钟到期。

```sh
npm run test:cloud-paws
npm test
npm run build:cloud-paws-server
GAME_API_BASE_URL=https://YOUR_GAME_API_HOST npm run build:app
```

正式构建使用既有账号 API 地址。`https://cloud-paws-test.invalid` 仅用于本地离线构建检查，不可发布。构建后的页面和资源使用相对地址，兼容 Windows/macOS 的 file:// 安装路径。

## 验证范围

游戏测试覆盖 60 段真实物理跳跃、相机方向、木杆碰撞不回档、移动/旋转平台承载，以及五人互相推动、独立存档和终点排序。房间测试覆盖同时加入上限、准备与房主权限、断线恢复/过期、无效输入和房间隔离。服务端 `test/game-cloud-paws.test.js` 使用真实认证 WebSocket 同时连接五人，检查第六人和未认证连接被拒绝、共享移动与重新连接。浏览器测试使用隔离测试身份验证组队界面。
